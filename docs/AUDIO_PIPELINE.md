# 六级听力音频流水线

## 目标

复用现有成套卷的音频结构，而不是只在软件里生成普通 TTS：

- 听力 A：2 段双人长对话，男女音色分开。
- 听力 B：2 篇篇章。
- 听力 C：3 篇讲话、报道或讲座。
- 每道题朗读题干，不朗读选项。
- 每题后保留约 13 秒作答时间。
- 每篇材料结束后先播 `Questions X to Y are based on ... you have just heard.`，再进入第一题。
- 合并输出单个 `Listening.mp3`。
- 成品应验证时长、文件大小、25 段停顿和每段停顿区间。

## 当前状态

应用内的试卷数据已经包含生成音频所需的全部文本和题号，但安装包尚未内置 TTS
运行时。现有 `Project_02_六级/模拟卷/scripts/build_audio.py` 可以作为基准实现，
其时间结构、双音色、选题播报和 13 秒停顿逻辑应原样保留。

2026-10-31 已接通桌面端整卷导出主链：

- 导出菜单新增“听力 MP3”；
- 逐句请求 TTS，并按 provider / endpoint / model / voice / text 的 SHA-256
  分句缓存，失败后可续跑；
- 每个分句统一修剪头尾静音、降为单声道并重采样到 24 kHz；
- 用统一时间伸缩校准目标词速，保持音高，13.1 秒作答停顿不参与伸缩；
- 使用纯 Rust MP3 编码器输出单个 `Listening.mp3`；
- 阿里云返回的占位 RIFF/data 长度 WAV 已做兼容修复，真实 Jennifer 请求已解码通过。

当前开发版可直接使用以下五类入口：

- 阿里云百炼；
- 小米 MiMo；
- 硅基流动；
- 随包 Kitten；
- 自定义 OpenAI 兼容本地或自建端点。

设置页像模型配置一样保留接口地址、模型和男女音色字段。云端 Key 按供应商分别
存入操作系统凭据库，互不复用。

2026-10-30 已完成供应商评估；2026-10-31 产品路线进一步确定为三层：

- 默认云端：阿里云百炼 `qwen3-tts-flash`，直接 HTTP 调用，英语男女声齐全；
  北京区每万字符 0.8 元，新账号有 1 万字符、90 天免费额度。
- 默认本地：随软件打包 Kitten TTS Nano 0.8 INT8。Python 运行时已打成约
  134 MiB 的单文件 sidecar，模型与音色库约 27 MiB；当前已在中文项目路径下
  实际合成成功。模型一次加载后批量合成全卷，失败句段继续复用缓存。
  Kokoro-82M INT8 保留为更自然的升级包，但解压后约 270 MiB、生成速度约慢 20 倍。
- 小米 MiMo：Base URL 为 `https://api.xiaomimimo.com/v1`，走
  `/chat/completions`，文本放在 `assistant` 消息，`audio.format=wav`。
  当前接入预置音色模型 `mimo-v2.5-tts`，推荐 Chloe / Milo。官方另有
  `mimo-v2.5-tts-voicedesign` 和 `mimo-v2.5-tts-voiceclone`，但它们分别要求
  文字音色描述或参考音频，不属于可直接无人值守跑完整卷的统一接口。
  官方文档当前标注“限时免费”，活动结束后价格未知。
- 硅基流动：Base URL 为 `https://api.siliconflow.cn/v1`，按 OpenAI
  `/audio/speech` 形状调用；默认 `FunAudioLLM/CosyVoice2-0.5B`。官方价格页
  显示 CosyVoice2-0.5B 与 MOSS-TTSD-v0.5 约 ¥0.05/千字符，低于阿里云当前
  ¥0.80/万字符。
- 用户接入：额外提供 OpenAI 兼容本地 TTS 端点，支持用户接入自己的
  Qwen3-TTS、Kokoro、GPT-SoVITS 或其他本地服务。约定
  `POST {baseUrl}/audio/speech`，提交 `model/text/voice/response_format=wav/speed`，
  返回 WAV；API Key 可为空。
- DeepSeek 当前没有 TTS 接口，不能复用现有文本模型 Key；需单独配置语音供应商。
- 详细来源、实测速度、音色、许可证和样本见
  `docs/TTS方案评估_2026-10-30.md` 与 `docs/audio-probes/`。

## 自动生成与文件位置

- 听力 A/B/C 全部通过并写入断点后，后台自动开始合成；剩余阅读和翻译继续生成，
  不必等整卷完成。
- 默认输出到试卷库同一目录：
  `papers/<试卷标题>-<paperId前8位>-Listening.mp3`。
- 分句缓存放同目录的 `.<文件名>.tts-cache`，失败后再次生成可续跑。
- 生成完成后应用内显示音频卡片和播放器，也可直接打开文件。

## 用户可调语速

- 默认 `170 词/分钟`。
- 可调范围 `140–200 词/分钟`，步长 1。
- 低语速用于听力基础训练，高语速用于进阶训练。
- 设置页和导出菜单都可调整；导出菜单会直接显示本次将生成的词速。
- 用户只调“目标词/分钟”，各 TTS 适配器内部换算成 `speed` 或时间伸缩参数；
  13 秒作答停顿、题号和试卷结构不随语速改变。
- “目标词/分钟”按材料及题干的发声加自然句间停顿计算，不把 25 个固定的
  13.1 秒作答停顿算进语速；这保证整个训练档位只改变真正听到的语流。
- 默认推荐阿里云 `Jennifer/Neil` 与 Kitten `Rosie/Bruno`。

## 阿里云断句控制

不能把整段原始文本直接交给模型依赖自动断句。合成前必须：

1. 统一空白、引号和破折号，但保留句末标点。
2. 保护 `Mr. / Dr. / e.g. / U.S.`、小数、时间、金额和首字母缩写，避免误切。
3. 按句号、问号、叹号切句；分号和冒号只作为次级停顿。
4. 每句单独送 TTS，长度保守限制在 500 字符以内。
5. 返回音频后统一修剪头尾静音，再按句间规则插入短停顿，不依赖模型自行处理标点。
6. 常见称谓、学历、日期、上下午时间、编号和缩写先转成更适合朗读的形式；
   数字、年份、金额仍需在整段合成后用 ASR 回查，发现异常只重做对应句段。

当前实现还会保护日期缩写、上下午时间、学位缩写、首字母缩写、编号与小数；
每个请求默认只承载一个句子，超长句优先在分号、冒号、逗号处切分。

单独的 `Conversation One.` 这类超短标题不能作为独立 TTS 请求直接播放，
否则会被异常拉长；应与第一句合并交给模型，或使用统一的题组播报声。

## 正式接入要求

1. 使用明确允许商业使用或符合本项目发行方式的 TTS。不要把非正式网页接口直接
   当作稳定的商业依赖。
2. 生成前先导出标准化的 `audio-source.json`，避免 TTS 层依赖试卷 JSON 的内部结构。
3. 逐段合成并按句子缓存，失败后从断点继续。
4. 使用 FFmpeg 拼接和插入静音，所有文件使用绝对路径。
5. 生成后自动检测：
   - 文件时长约 25.5-27.5 分钟；
   - 25 段作答停顿且每段约 13.2-13.6 秒；
   - 7 条题组播报齐全；
   - `Listening.mp3` 可被解码。
6. 终版在试卷页和文件元数据中标注“AI 辅助、合成语音、非官方”。

## Edge 路线

`edge-tts` 可以继续用于个人本地实验，但不进入正式发行默认路线。它使用的是
Edge 在线朗读服务而非微软公开稳定 API，接口和访问策略可能变化，软件自身为
LGPLv3；需要微软音色正式发行时应改接 Azure Speech。

## 未完成原因

阿里云与 Kitten 端点主链均已完成，但正式发布前仍需用真实 25 题整卷完成时长、
ASR、25 段停顿和 7 条题组播报验收。Kitten 的 PyInstaller 打包和中文路径兼容
已经实测；发布时仍必须随附 eSpeak NG / phonemizer 的 GPL-3.0 许可与对应源码
获取方式。
