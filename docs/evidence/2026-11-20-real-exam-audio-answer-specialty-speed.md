# 三套真题音频、答案与 Reading C 专项修复

## 现场问题

- 三套合订 PDF 对应两份听力音频，旧界面只能选一份。
- 2025 年 6 月第三套官方没有 Listening，导入时被当成缺板块。
- 答案页虽然就在同一 PDF 的第 23 页，但旧流程仍先联网搜索；搜索无结果后所有
  客观题保持 missing，无法创建试卷。
- Reading C 专项从 18:15 开始，连续 5 次整组生成，到 18:35 仍失败，累计约 20 分钟。

## 根因

1. `listeningAudioPath` 和 `ImportedSetDraft` 都是单值，无法表达“第一套音频 A、第二套音频 B、
   第三套无音频”。
2. `importedDraftIssues()` 把 `full` 解释成“八个板块必须全部存在”，与该套官方真题明确
   注明“不再重复出现听力”相冲突。
3. 第 23 页答案速查落在第三套页范围内，被当作题纸正文送给模型；同时本地答案模型只允许
   A-D，Reading A/B 的 E-O 答案无法进入答案表和题库。
4. Reading C 遇到“选项内容正确但固定字母位置不一致”时，旧解析直接判失败，外层随后重新
   生成两篇全部题目。诊断中的 attempt 1-5 每次约 92-204 秒。

## 修复

- 导入对话框一次可选多份音频；按文件名中的“第一套/第二套”优先匹配，否则按套装顺序分配。
  每套卡可单独改为任意已选音频或“无听力音频”。
- `full` 导入只校验实际检测到的板块数量，不再强制存在 Listening。
- 先识别并移除“答案速查/参考答案”页，再按“第一套/第二套/第三套”解析答案。
- 卷内答案映射到 Listening A/B/C、Reading A/B/C，状态记为 `official`，优先于旧答案库和网络结果。
- Answer row / bank 支持 A-O；同时归一化 OCR 常见的 `0 -> O`、`1 -> I`。
- 搜索仍作为无答案页时的后备；增加“考试年月 + 套次 + 六级真题答案”的通用查询。
- Reading C 两篇正文和两组五题分别并行生成；风险复核分组并行发出。
- 模型给出的正确选项会由程序移动到固定答案位，并同步改写 A)-D) 与“故选 X”。
- 质量检查失败时只重修 Q46-50 或 Q51-55 对应五题组，不再每次重跑整组。
- Reading C ETA 从 5 分钟调整为 12 分钟；超过初始预计后显示“正在自动修复重试”，
  不再长期显示剩余 0 分钟。

## 验证

- 真实 OCR 第 23 页恢复 140 个答案：第一套 55、第二套 55、第三套 Reading 30。
- OCR 混淆 `35.0`、`38.1`、`30.1`、`42.0` 均正确归为 O/I。
- 两音频 + 三套时得到 `[audio1, audio2, 无]`，选中顺序颠倒也能按文件名纠正。
- 无 Listening 的完整套卷通过导入校验。
- Reading C 固定答案位置回归：A/B/C/D 内容会移动到计划字母并同步解析。
- 前端 63 文件 / 419 项测试、TypeScript、Rust 41 项常规测试、生产构建和独立 debug 编译通过。
