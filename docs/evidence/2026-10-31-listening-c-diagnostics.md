# 2026-10-31 听力 C 解析失败与持久化诊断

## 用户现场

- 已安装版本：`0.3.2`
- 数据目录：`E:\Download\CET-6`
- 试卷：`eb32c436-372b-40f6-8f54-ad4a9b6ac830`
- 断点只保存了 blueprint、writing、listening-a、listening-b。
- 失败信息：
  - 错误码：`jsonRetryExhausted`
  - 失败阶段：听力 C
  - 检查：解析为中文、含英文依据且写明正确字母
  - 具体题号/缺项：空

## 原因

该检查是一个整组布尔校验。只要有一道听力题缺中文、缺英文引述或
“故选 X”与 `correctAnswer` 不一致，就返回整组失败，但没有把具体题号和原因写回错误详情。
旧安装包也没有保存模型原始回复，因此现有断点无法还原是哪一道题失败，只能重新请求。

同一真实蓝图复跑时曾出现：

- 第一次三篇合计 1294 词，低于 1300；
- 第二次通过。

说明该阶段存在正常的偶发质量波动，但旧流程没有留下可供事后查询的完整现场。

## 修复

### 更具体的校验

听力解析失败现在逐题返回：

- 缺中文解析；
- 缺英文原文引述；
- 缺“故选 X”；
- 写成“故选 A”，但正确答案为“故选 D”。

### 更明确的生成约束

听力提示新增硬要求：

- 每题解析必须包含中文分析；
- 必须包含该题组原文中的短英文引述；
- 末尾必须是 `故选 X。`；
- X 必须等于 `correctAnswer`。

听力阶段失败后的定向修复次数由 3 次提高到 5 次。

### 不再依赖复跑：持久化诊断

每个失败尝试写入：

`generation/cet6/diagnostics/{paperId}/`

每份 JSON 包含：

- stage、attempt、attemptLimit；
- provider、model；
- startedAt、finishedAt、durationMs；
- network_error 或 validation_failed；
- 完整校验错误；
- 发给模型的完整 messages；
- 模型原始 `rawReply`。

不写 API Key，也不写 Authorization 请求头。诊断写盘失败不会覆盖原始生成错误。

错误卡现在直接显示诊断目录，并提供“打开诊断目录”按钮，用户无需重跑模型。

### 自动定向修复

后续尝试不再从空白重新生成，而是把上一轮完整 JSON 和具体校验失败一起回传给模型：

- 保留已经通过的正文、题目、选项、答案和解析；
- 只修失败项；
- 保持同一阶段、同一结构和同一 JSON 形状；
- 要求重新核对每题 `故选 X` 与 `correctAnswer`。

蓝图、写作、听力 A/B/C、阅读 A、阅读 B/C 和翻译阶段均使用这条“自我修复上一版 JSON”
路径。仍然失败时才进入下一次完整重构或最终报错。
