# 六级智卷后续升级清单

## 自动更新推送

状态：已记录，暂不实现。

目标不是简单地下载并运行一个远程 EXE，而是建立可验证、可回滚的 Windows 更新链：

1. 使用独立更新清单，包含版本号、最低可升级版本、下载地址、SHA-256、文件大小、
   发布日期和更新说明。
2. 更新清单必须带数字签名；安装包也必须做代码签名，客户端只接受签名和哈希都通过的文件。
3. 默认先提示用户，由用户确认后下载；下载完成再次核对哈希，再交给安装器。
4. 生成试卷、导出 PDF 或合成音频期间不得静默重启。
5. 保留上一版安装包和回滚入口；升级失败时恢复原版本，不触碰用户数据目录。
6. 更新服务不可用时必须静默降级，不能阻断离线使用和现有功能。
7. 首次上线前需要确定二进制托管位置、签名证书、发布回滚流程和隐私说明。

当前版本只保留手工安装升级，不访问远程更新地址。

## 商户号预下单动态赞赏码

状态：暂缓。用户目前只有个人身份证，无法注册微信支付普通商户号；当前改用爱发电外部支持页。

- 个人静态收款码不能当作“商户号预下单动态码”使用，也不能由客户端只刷新图片来伪装实时订单。
- 正式方案必须由持有商户号的收款主体通过微信支付 Native 下单或支付宝当面付/统一收单创建订单，
  服务端返回二维码内容或二维码图片，并保存订单号、金额、有效期和支付结果。
- 商户私钥、API v3 Key、平台证书等只能放在可信后端，不能打包进 Windows 客户端。
- 客户端只负责向后端请求下单结果、展示二维码、轮询订单状态和刷新过期二维码。
- 后端必须验证微信/支付宝回调签名，不能仅相信客户端返回的“已支付”。
- 赞赏必须保持非强制，不能解锁功能；若实际属于经营性收款，还需要按支付平台要求完成主体、
  类目、结算、退款、税务和用户协议配置。
- 上线前需明确服务地址、HTTPS、订单数据库、回调公网地址、退款/客服流程和日志脱敏策略。
- 安装包不再包含或读取个人静态收款码。
- 未来取得营业执照和微信支付商户号后，再恢复商户预下单动态码；前置条件见
  `docs/PAYMENT_BACKEND.md`。
