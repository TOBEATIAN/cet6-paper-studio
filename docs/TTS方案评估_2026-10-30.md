# 六级听力 TTS 方案评估（2026-10-30）

## 结论

采用“阿里云 BYOK 为主、Kitten 随软件本地运行、自定义本地 TTS 可选接入”的三层
路线。该结论包含官方资料核对、云端真实接口调用和本机本地模型基准测试：

1. 默认使用阿里云百炼 `qwen3-tts-flash`。它可直接从桌面端 HTTP 调用，单次最多
   600 字符，支持英语男女音色，返回可在 24 小时内下载的音频 URL。
2. 将 Kitten TTS Nano 0.8 INT8 作为随软件提供的本地默认方案，优先保证断网、
   无第二家 API Key 的用户也能生成；质量为不够时再提供 Kokoro-82M INT8 升级包。
3. 增加 OpenAI 兼容的本地 TTS 端点，允许有独立显卡的用户接入自己的
   Qwen3-TTS、Kokoro、GPT-SoVITS 等服务。
3. DeepSeek 当前没有 TTS 接口，不能复用现有 DeepSeek Key 生成听力音频，需要单独
   配置语音供应商。

## 云端方案

### Qwen3-TTS-Flash

官方资料：

- [非实时语音合成指南](https://help.aliyun.com/zh/model-studio/qwen-tts)
- [Qwen3-TTS API](https://help.aliyun.com/zh/model-studio/qwen-tts-api)
- [音色列表](https://help.aliyun.com/zh/model-studio/qwen-tts-voice-list)
- [模型价格](https://help.aliyun.com/zh/model-studio/model-pricing)

关键事实：

- 北京地域模型 ID：`qwen3-tts-flash`
- 非实时 HTTP 接口，一次请求最多 600 字符
- 返回 `output.audio.url`，下载链接有效期 24 小时
- 英语音色包括男声 `Ethan`、`Aiden`、`Ryan`，女声 `Cherry`、`Serena`、
  `Jennifer` 等
- 北京地域价格：每万字符 0.8 元；新开通账号有 1 万字符、90 天免费额度

2026-10-30 本机实测同一段 25 词英文：

- 调用并下载总耗时约 2.8 秒
- 音频 9.36 秒、24 kHz 单声道 WAV
- 自动转写与原文一致，语速约 160 词/分钟
- 估算一套约 25 分钟、1.8 万字符的听力约 1.44 元

试用样本：

`docs/audio-probes/Qwen3-TTS-Flash-Ethan.mp3`

### 适用方式

- API Key 存入 Windows 凭据库，由 Rust 后端读取并直接请求，不进入浏览器或日志。
- 按句子切分，单段保守限制 500 字符，逐段合成并缓存。
- 音频 URL 返回后立即下载；不能把 24 小时临时链接写进试卷。
- 整卷合成失败时可只重试缺失句段。

## 本地方案首选

### Kitten TTS Nano 0.8 INT8

官方资料：

- [Kitten TTS 项目](https://github.com/KittenML/KittenTTS)
- [轻量 ONNX 模型说明](https://github.com/KittenML/KittenTTS/blob/main/docs/onnx-models.md)
- [Nano INT8 模型](https://huggingface.co/KittenML/kitten-tts-nano-0.8-int8)

许可证与体积：

- 代码：Apache-2.0
- Nano INT8 模型卡：Apache-2.0
- 模型文件约 24.4 MB，音色库约 3.28 MB
- 本机最小 Python 运行环境加模型约 191 MiB
- 8 个英语音色，男声包括 Jasper、Bruno、Hugo、Leo

本机实测（同一段 25 词英文，`speed=1.2`）：

- 模型缓存后单句合成约 0.53 秒
- 音频 10.61 秒，141 词/分钟
- RTF 约 `0.05`，即约为实时的 20 倍
- 自动转写与原文一致
- 进程工作集约 330 MiB，提交内存约 1.1 GiB

试用样本：

`docs/audio-probes/KittenTTS-Nano-INT8-Jasper-speed1.2.mp3`

这是目前最符合“普通电脑、离线、体积小”的候选。它仍通过 `espeak-ng` 做英文音素化，
而 eSpeak NG 是 GPL-3.0；因此正式闭源发行时，要么按 GPL 要求随附对应源码和许可证，
要么把音素化做成独立程序并保留源码义务，要么换成许可证更宽松的 G2P 层。

## 本地高质量后备

### Kokoro-82M + kokoro-onnx

官方资料：

- [Kokoro 项目](https://github.com/hexgrad/kokoro)
- [kokoro-onnx](https://github.com/thewh1teagle/kokoro-onnx)
- [模型文件发布页](https://github.com/thewh1teagle/kokoro-onnx/releases/tag/model-files-v1.1)

许可证与体积：

- `kokoro-onnx` 代码：MIT
- Kokoro-82M 权重：Apache-2.0
- 量化模型 `kokoro-v1.0.int8.onnx`：114,119,327 字节（约 109 MiB）
- 音色库 `voices-v1.0.bin`：28,214,398 字节（约 27 MiB）
- 本机 Python 运行依赖：约 138 MiB
- 解压后合计约 270 MiB，压缩安装包预计也明显大于当前 5 MB 主程序

能力与实测：

- 纯 CPU、无需 GPU；54 个音色
- 英语男女声完整，可用于长对话、篇章和讲座
- 本机 Intel i7-14650HX、24 线程、INT8 模型的实测 RTF 约 `1.16`
  （生成 1 秒音频约耗 1.16 秒 CPU 时间）
- 一套 25 分钟听力约需 29 分钟生成；4 核老电脑可能接近 45–60 分钟
- 进程峰值工作集约 0.6 GB，提交内存约 1.4 GB
- 自动转写与原文一致，语速约 142 词/分钟

试用样本：

`docs/audio-probes/Kokoro-82M-int8-am_michael.mp3`

Kokoro 当前实现同样使用 eSpeak NG，因此存在与 Kitten 相同的 GPL 依赖边界。它的优势是
54 个音色和更自然的长篇表现，代价是体积和生成时间约为 Kitten 的数倍。

## Qwen3-TTS 本地开源版

官方资料：

- [Qwen3-TTS 项目](https://github.com/QwenLM/Qwen3-TTS)
- [0.6B CustomVoice 模型](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-0.6B-CustomVoice)
- [1.7B CustomVoice 模型](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice)

事实：

- 代码和模型权重均为 Apache-2.0。
- 0.6B CustomVoice 主模型 1,811,626,576 字节，语音 tokenizer 682,293,092 字节，
  两者合计约 2.49 GB。
- 1.7B CustomVoice 主模型 3,833,402,552 字节，加 tokenizer 后约 4.52 GB。
- 官方快速上手默认 `cuda:0`、`torch.bfloat16` 和 FlashAttention 2；支持
  `Ryan`、`Aiden` 两个英语男声，并可接受自然语言语气与语速指令。

判断：Qwen3-TTS 本地版质量上限高、授权清楚，但它不是小巧的“所有电脑默认可用”
方案。应作为有独立显卡用户的可选高质量包，Kitten 仍负责普通电脑离线后备。

### 本地部署注意

Windows 实测发现 `espeakng-loader` 在含中文的目录路径下会错误读取内置数据路径；
将同一环境移到纯 ASCII 路径后可以正常运行。因此本地语音包不能直接解压到项目中文
目录，应安装到独立 ASCII 缓存目录，或改成不依赖该路径解析方式的原生运行时。

正式发布时不能要求用户自行安装 Python。应把最小 Python 解释器和
`kokoro-onnx` 依赖打成独立 sidecar，或改用 Rust/C++ ONNX 实现；模型与音色作为
可选下载资源，并在下载完成后校验 SHA-256。

## 排除或降级的方案

- Piper 当前主仓库为 GPL-3.0，不适合作为闭源商业分支的直接嵌入依赖；旧版 MIT
  代码与具体音色模型仍要逐个核对授权，维护成本高于 Kokoro。
- Supertonic 代码 MIT、模型 OpenRAIL-M，速度和小体积有吸引力，但上游仓库已经归档，
  不适合作为长期维护的新项目底座。
- Azure Speech 可以直接调用，官方免费层每月有 50 万字符额度，但国内注册、支付和
  网络体验不如阿里云，只作为企业用户备选。
- `edge-tts` 可以用于个人生成，但不作为正式发行依赖：它调用 Edge 浏览器的在线
  朗读服务，不是微软公开承诺的 API；接口和访问策略可能随时变化，软件自身为
  LGPLv3。若要使用微软音色做合规发行，应改接 Azure Speech 官方 API。

## 建议的落地顺序

1. 先接 `qwen3-tts-flash`，让用户填自己的百炼 Key，完成“一套卷 → 25 个停顿的
   Listening.mp3”端到端流水线。
2. 把 TTS Key、区域、男女声和语速做成独立设置；不要求与 DeepSeek Key 相同。
3. 在基础安装包内集成 Kitten sidecar；Qwen/Kokoro 等大模型继续由用户通过自定义
   OpenAI 兼容端点接入，避免让所有用户承担数 GB 模型和显卡要求。
4. 无论云端还是本地，都在试卷、音频元数据和商品页标明“AI 辅助、合成语音、
   非官方资料”。

## 验证边界

- 本文价格和接口字段来自 2026-10-30 可访问的官方文档。
- 本地 RTF 是本机特定 CPU 的单次实测，不代表所有电脑。
- 本地模型授权依据上游仓库当前声明；正式打包前仍需把 `LICENSE`、模型卡和
  `NOTICE` 纳入发布清单，并单独处理 eSpeak NG 的 GPL-3.0 义务。
